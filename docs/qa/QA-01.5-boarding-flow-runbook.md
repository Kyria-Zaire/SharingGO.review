## 1. Synthèse exécutive

Le flow boarding V1 est **opérationnel** et réparti sur trois surfaces :

| Surface | Rôle |
|---------|------|
| **Passager** (`:5174`) | Affiche le QR (JWT) · lit le statut réservation |
| **Admin / Driver** (`:5173` `/boarding`) | Scan manuel JWT · validate / consume |
| **Backend** (`:3000`) | Signature HS256 · règles métier · passage `CONFIRMED` → `USED` |

Le passager **ne décode pas** le JWT localement : le QR encode la chaîne JWT retournée par l’API.  
La **validation cryptographique** et le **contrôle métier** sont **100 % serveur** (`verifyBoardingToken` + eligibility).

## 2. Cartographie des routes API

### 2.1 Boarding (`/api/boarding`)

Montage : `backend/src/app.ts` → `boardingRouter`.

| Méthode | Route | Auth | Rôles | Effet |
|---------|-------|------|-------|-------|
| `GET` | `/api/boarding/offline-capabilities` | Public | — | Manifest offline V1 (`ONLINE_FIRST`) |
| `POST` | `/api/boarding/validate` | Cookie session | `ADMIN`, `SUPER_ADMIN`, `DRIVER` | Contrôle JWT **sans** écrire en DB |
| `POST` | `/api/boarding/consume` | Cookie session | `ADMIN`, `SUPER_ADMIN`, `DRIVER` | Contrôle + `Reservation.status = USED` (transaction `FOR UPDATE`) |
| `GET` | `/api/boarding/:reservationId/qr` | Cookie session | **Propriétaire** | Contrat QR (`qr.payload` = JWT signé) |
| `GET` | `/api/boarding/:reservationId/token` | Cookie session | **Propriétaire** | JWT brut (fondation S2-T1, hors image QR) |

**Body validate / consume :**

```json
{ "boardingToken": "<JWT HS256>" }
```

**Réponses métier :** HTTP **200** même si `valid: false` (raison dans le body).  
`CONVOYEUR` (passager) → **403** sur validate/consume.

### 2.2 Billet / réservation passager (`/api/reservations`)

| Méthode | Route | Usage boarding |
|---------|-------|----------------|
| `GET` | `/api/reservations` | Historique · filtre `status`, `upcoming`, `past` |
| `GET` | `/api/reservations/:id` | Détail billet · **statut** affiché passager |
| `GET` | `/api/reservations/pending/:id` | Pending TTL 2 min (hors boarding QR) |
| `POST` | `/api/reservations/pending` | Création pending (pré-paiement) |
| `DELETE` | `/api/reservations/pending/:id` | Annulation pending |
| `POST` | `/api/reservations/book-with-subscription` | CONFIRMED direct (abo) |

**Source statut billet :** champ `status` de `GET /api/reservations/:id` (enum Prisma `ReservationStatus`).

## 4. Décodage QR / JWT

### 4.1 Génération (serveur)

Fichier : `backend/src/modules/boarding/boarding.service.ts` → `generateBoardingToken()`

Prérequis :

1. Réservation `CONFIRMED`
2. Paiement `SUCCEEDED`
3. Fenêtre ouverte : `departureTime + 10 min` (`BOARDING_GRACE_MS`)
4. Propriétaire (`userId` match)

Étapes :

1. Token opaque `Reservation.boardingToken` créé en DB si absent (`generateOpaqueToken()`)
2. JWT signé HS256 via `signBoardingJwt()` (`boarding-jwt.ts`)

### 4.2 Claims JWT

| Claim | Signification |
|-------|---------------|
| `sub` | `reservationId` |
| `typ` | `"boarding"` (obligatoire) |
| `uid` | `userId` passager |
| `tid` | `tripId` |
| `bt` | token opaque DB (révocation si mismatch) |
| `iat` | émission (unix s) |
| `exp` | expiration = **départ + 10 min** (unix s) |

Secret : `BOARDING_JWT_SECRET` (≥ 32 caractères, `env.boardingJwtSecret`).

### 4.3 Vérification (serveur uniquement)

Fichier : `backend/src/modules/boarding/boarding-jwt.ts` → `verifyBoardingToken()`

1. Split `header.payload.signature`
2. HMAC-SHA256 + `timingSafeEqual`
3. Parse JSON payload · valide claims requis
4. Rejette si `exp * 1000 <= Date.now()` → `EXPIRED_TOKEN`

Puis services métier :

- **validate** : `boarding.validation.service.ts`
- **consume** : `boarding.consumption.service.ts` + `boarding-eligibility.ts`

Contrôles post-JWT :

- Réservation existe · `bt` = `boardingToken` DB
- `userId` / `tripId` cohérents
- Statut `CONFIRMED` (validate) ou gestion `USED` (consume)
- Trip non soft-deleted
- Fenêtre boarding ouverte
- Paiement `SUCCEEDED`

### 4.4 Côté passager

**Aucun décodage JWT.** Le frontend encode le JWT dans le QR tel quel :

```tsx
<QRCode value={boardingData.qr.payload} />
```

Expiration affichée via `expiresAt` API + countdown client (`useBoardingCountdown`).

## 5. Statuts réservation

### 5.1 Enum Prisma (`ReservationStatus`)

```prisma
PENDING | CONFIRMED | CANCELED | USED | EXPIRED
```

> **Note orthographe :** Prisma/API passager = `CANCELED` (une L). OpenAPI admin partiel utilise parfois `CANCELLED` — à normaliser hors scope QA-01.5.

### 5.2 Rôle dans le boarding

| Statut | Boarding QR (`GET …/qr`) | `POST …/validate` | `POST …/consume` | UI passager |
|--------|--------------------------|-------------------|------------------|-------------|
| **PENDING** | 409 `RESERVATION_NOT_CONFIRMED` | `RESERVATION_NOT_CONFIRMED` | `RESERVATION_NOT_CONFIRMED` | Pas de billet QR |
| **CONFIRMED** | JWT émis si fenêtre OK | `valid: true` si règles OK | Passe en **USED** | CTA billet actif |
| **USED** | 409 `RESERVATION_NOT_CONFIRMED` | `RESERVATION_NOT_CONFIRMED` | `BOARDING_ALREADY_USED` (idempotent si même JWT) | « Billet utilisé » |
| **CANCELED** | 409 `RESERVATION_NOT_CONFIRMED` | `RESERVATION_NOT_CONFIRMED` | `RESERVATION_NOT_CONFIRMED` | « Réservation annulée » |
| **EXPIRED** | 409 `RESERVATION_NOT_CONFIRMED` | `RESERVATION_NOT_CONFIRMED` | `RESERVATION_NOT_CONFIRMED` | Label fallback |

### 5.3 Observations audit

| Statut | Assignation code V1 |
|--------|---------------------|
| **CONFIRMED** | Webhook Stripe ticket · abo `book-with-subscription` |
| **USED** | `consumeBoardingTokenSubmission` uniquement |
| **CANCELED** | Admin `admin-reservations.service` (annulation) |
| **EXPIRED** | **Présent en enum · non assigné** dans le code backend audité (2026-06-19) |
| **PENDING expiré** | Erreur API `PENDING_EXPIRED` (410) — **pas** le statut DB `EXPIRED` |

### 5.4 Codes erreur boarding (distincts des statuts DB)

| Code | HTTP (QR) | Contexte |
|------|-----------|----------|
| `BOARDING_EXPIRED` | 410 | Fenêtre départ + 10 min dépassée |
| `BOARDING_NOT_AVAILABLE` | 409 | Paiement non SUCCEEDED |
| `RESERVATION_NOT_CONFIRMED` | 409 | Statut ≠ CONFIRMED |
| `EXPIRED_TOKEN` | — | JWT `exp` dépassé (validate/consume body) |
| `BOARDING_WINDOW_EXPIRED` | — | JWT valide mais fenêtre trajet fermée |
| `BOARDING_ALREADY_USED` | — | Second scan même JWT après USED |
| `TOKEN_REVOKED` | — | `bt` ne match plus DB |
