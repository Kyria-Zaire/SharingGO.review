# S1.5-T2 — Payment Retrieval / Status API

Ticket : lecture seule des paiements utilisateur, avec lien optionnel vers réservation, trajet et ligne.

## Objectifs

- `GET /api/payments` — liste paginée, filtres `status` / `type`
- `GET /api/payments/:id` — détail owner-only
- Serializers safe (aucun identifiant Stripe interne)
- Préparation dashboard / mobile « Mes paiements »

## Relation Payment ↔ Reservation (S1-T4)

| Étape | Modèle |
|-------|--------|
| Checkout | `Payment` PENDING + `stripeCheckoutSessionId` (interne) |
| Webhook | `Payment` → SUCCEEDED, `reservationId` renseigné |
| Historique résa | S1.5-T1 `GET /api/reservations` |
| **Historique paiement** | S1.5-T2 `GET /api/payments` (ce ticket) |

Aucune modification webhook ni Stripe.

## Ownership

- Toutes les requêtes : `WHERE userId = req.user.id`
- Détail : `findFirst({ id, userId })` → **404 `PAYMENT_NOT_FOUND`** si absent ou autre user

## Routes

| Méthode | Route | Auth |
|---------|-------|------|
| GET | `/api/payments` | `requireAuth` |
| GET | `/api/payments/:id` | `requireAuth` |
| POST | `/api/payments/checkout` | inchangé (S1-T4) |

## Query params — liste

| Param | Règles |
|-------|--------|
| `status` | `PaymentStatus` optionnel |
| `type` | `PaymentType` optionnel |
| `limit` | 1–100, défaut 50 |
| `offset` | ≥ 0, défaut 0 |

Tri : `createdAt` **desc**

## Serializers safe

### Payment (exposé)

`id`, `status`, `type`, `amount`, `currency`, `createdAt`

### Non exposé

`stripePaymentIntentId`, `stripeCheckoutSessionId`, `stripeInvoiceId`, `stripeSubscriptionId`, metadata / payloads webhook, `boardingToken`

### Reservation minimale (si liée)

`id`, `status`, `trip` (+ `line`) — via `serializeReservationMinimal`

## Pourquoi masquer les IDs Stripe ?

- Clés de réconciliation internes / support ops
- Risque de fuite si loggées côté client
- L’utilisateur n’a besoin que du **statut métier** et du **lien trajet**

## Erreurs

| Code | HTTP |
|------|------|
| `UNAUTHORIZED` | 401 |
| `VALIDATION_ERROR` | 400 |
| `PAYMENT_NOT_FOUND` | 404 |

## Exemples curl

```powershell
curl.exe -b cookies.txt http://localhost:3000/api/payments
curl.exe -b cookies.txt "http://localhost:3000/api/payments?status=SUCCEEDED&type=TICKET&limit=10"
curl.exe -b cookies.txt http://localhost:3000/api/payments/PAYMENT_ID
curl.exe http://localhost:3000/api/payments
```
